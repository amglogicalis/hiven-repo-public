1. Visión General & Filosofía Soberana

Hiven V3 es el motor de ingeniería de software autónomo multi-agente de coste \$0 del ecosistema Terra. Su propósito es resolver prácticamente cualquier tarea de desarrollo (desde utilidades aisladas hasta refactorizaciones complejas de sistemas concurrentes) con una tasa de efectividad real cercana al 99%.

Principio Fundamental: Hiven no es un chatbot que adivina código a ciegas; es un enjambre determinista que descompone tareas en grafos acíclicos (Task DAG), aplica parches quirúrgicos mínimos, valida su propio código en sandboxes efímeros y se auto-corrige ante cualquier error antes de publicar una Pull Request.

2. Pipeline de 4 Fases

Cada misión despachada atraviesa cinco estados estrictos y trazables:

  • Fase 0 (Deterministic Extractor): Inspecciona la topología del repositorio, paquetes instalados, archivos de configuración (package.json, tsconfig.json, etc.) y árboles sintácticos (AST) sin depender de alucinaciones del modelo.
  • Fase 1 (Swarm Architect): Analiza la misión y consulta la memoria Honeycombs para extraer directivas previas. Divide la instrucción en un Grafo de Tareas (Task DAG) con dependencias ordenadas.
  • Fase 2 (Parallel Coders): Nodos Kōmbee concurrentes escriben código exclusivamente mediante bloques quirúrgicos SEARCH/REPLACE. Esto garantiza que nunca se borren imports preexistentes, comentarios ni lógica no relacionada.
  • Fase 3 (Shadow Sandbox): Ejecuta de forma aislada las suites de verificación y tests unitarios. Si todos los tests pasan en verde (exit 0), avanza a la Fase 4.
  • Fase 4 (Consolidator): Consolida los parches, genera el commit atómico, sube la rama remota y abre la Pull Request oficial en GitHub con un resumen estructurado de cambios.

3. Bucle de Auto-Sanación (Self-Healing Loop)

El pilar principal que eleva la efectividad de Hiven al 99% es su bucle de auto-recuperación:

Si la Fase 3 detecta un fallo de compilación, sintaxis o error en los tests (exit code !== 0), Hiven no da por perdida la misión ni emite una PR rota. En su lugar:

  1. Captura el stderr, el stack trace y las aserciones fallidas de la prueba.
  2. Sintetiza la causa raíz del fallo y la almacena temporalmente como un dontDirective en Honeycombs para no repetir la misma equivocación.
  3. Reinyecta el contexto de error a un sub-enjambre de corrección quirúrgica.
  4. Genera un parche de reparación y repite la prueba en el Sandbox (hasta el número de reintentos configurado).
  5. Una vez que la suite concluye con éxito, guarda el aprendizaje ganador como doDirective.

5. Manual de Buen Prompting para Enjambres Autónomos

La calidad y velocidad de resolución de Hiven dependen directamente de cómo estructures la instrucción. Los agentes autónomos prosperan cuando les das criterios de éxito verificables, no intenciones difusas.

La Fórmula en 4 Pasos de un Prompt de Alto Rendimiento:

  1. Ubicación & Módulo Objetivo: Especifica el archivo o directorio a crear/modificar (ej. src/utils/math.ts).
  2. Contrato de la Interfaz: Define nombres de funciones, tipos de datos esperados, parámetros y valores de retorno.
  3. Casos Límite & Restricciones: Manejo de errores (qué excepciones lanzar, timeouts, validación de nulos o strings vacíos).
  4. Criterio de Validación: Indica qué suite de tests debe acompañar al código.
❌ Mal Prompt (Vago & Ambiguo)

Crea un validador de emails y ponle pruebas.

Problema: No especifica archivo, estándar de regex, si debe lanzar excepción o retornar booleano, ni qué casos edge probar.

✅ Buen Prompt (Específico & Determinista)
Crear en src/validators/email.js la función isWorkEmail(email). - Debe validar formato RFC 5322 y rechazar dominios gratuitos (gmail, yahoo, hotmail). - Retornar { valid: boolean, domain: string, reason?: string }. - Si el input no es string, lanzar TypeError. - Exportar en ESM y crear suite de tests con al menos 6 casos límite.
❌ Mal Prompt (Refactorización)

Optimiza la base de datos y que vaya más rápida.

Problema: No define qué consultas optimizar ni qué métricas o índices añadir.

✅ Buen Prompt (Refactorización Quirúrgica)
En src/db/repository.ts, refactorizar getUserSessions(userId): - Sustituir la concatenación de queries por un pool con prepared statements. - Implementar caché LRU en memoria con TTL de 60 segundos. - Mantener exactamente la misma firma y tipo de retorno UserSession[]. - Ejecutar npm run test:db en el Sandbox.

6. Hiven Honeycombs: Memoria de Dos Niveles

Honeycombs es el sistema de memoria colectiva de Hiven. No almacena fragmentos de código fuente pesados, sino reglas heurísticas compactas indexadas por lenguaje (hive_patterns:{ext}):

  • doDirective: Buenas prácticas y patrones de diseño que superaron las pruebas unitarias.
  • dontDirective: Antipatrones y trampas que provocaron errores en el sandbox, aprendidos durante el bucle de auto-sanación.

Los Dos Niveles de Operación:

  • Nivel 1 (Memoria Local Privada): Se almacena en tu propia caché y en el repositorio privado .hiven-storage. Te permite inspeccionar cada patrón y purgar de forma granular aquellos que ya no te interesen con el botón 🗑️.
  • Nivel 2 (Mente Colmena Global): Conexión federada con la red colectiva de Terra. Al activarla mediante el interruptor superior (tras aceptar el modal de confirmación y privacidad), tu enjambre comparte sus directivas aprendidas y se nutre del conocimiento de otros desarrolladores sin exponer jamás credenciales, tokens ni código sensible.

7. Consumo Externo (SDK TypeScript & Swarm REST API para Sphexn)

Hiven está diseñado para ser consumido como un servicio autónomo tanto por desarrolladores humanos como por otros agentes inteligentes del ecosistema Terra (como Sphexn):

Opción A: SDK Programático (terra-hiven)

npm i terra-hiven

En tu código TypeScript o JavaScript:

import { Hiven } from "terra-hiven";
const hiven = new Hiven();
const res = await hiven.dispatchSwarm({ repo: "org/repo", instruction: "..." });

Opción B: Swarm REST API (HTTP JSON)

Al iniciar el servidor local con hiven console o hiven serve, se habilita la API REST oficial en http://localhost:7460:

  • POST /api/v1/swarm/dispatch: Despacha un enjambre recibiendo el JSON de configuración.
  • GET /api/v1/swarm/:id: Consulta el estado en tiempo real, rondas de auto-sanación y URL de la PR.
  • GET /api/v1/honeycombs/patterns?lang=ts: Devuelve los Do's & Don'ts aprendidos para TypeScript.
  • GET /api/v1/health: Comprobación de estado operativo del motor.

8. Preguntas Frecuentes & Consejos de Producción (FAQ)

¿Hiven tiene algún coste de infraestructura mensual?

No. Funciona bajo el modelo de coste marginal $0 de Terra. Utiliza los minutos gratuitos de GitHub Actions, almacenamiento soberano en repositorios Git y GitHub Pages.

¿Por qué las ejecuciones directas tardan apenas unos segundos?

Porque la extracción de dependencias y los diffs quirúrgicos se computan en memoria RAM ($O(1)$) y el Shadow Sandbox valida el código en procesos locales efímeros sin la sobrecarga de arranque de máquinas virtuales en la nube.

¿Qué permisos necesita mi GitHub PAT?

Requiere exclusivamente los scopes de repo (para crear ramas, commits y Pull Requests) y workflow (para despachar GitHub Actions si usas el modo nube).

¿Cómo garantizo que Hiven no borre código existente?

Hiven utiliza bloques de búsqueda y reemplazo contextuales con diffs quirúrgicos (`applySearchReplace`). Nunca reescribe un archivo completo de cero a menos que sea un archivo de nueva creación.
